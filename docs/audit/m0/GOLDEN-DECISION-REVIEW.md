## Cross-cutting questions for the reviewer

1. **Kernel trust in `verified_by`** (case 10): should the kernel verify a PrincipalProof itself rather than trust the adapter-set string?
2. **Approval binding omits `requested_capabilities`** (case 20): should the approval request id and ApprovalGrant bind them?
3. **require_approval outranks permit** (case 8): confirm as organization-wide semantics.
4. **`deadline_at` is not evaluated** by the kernel in any case; an expired request is decided normally. Decide whether expiry belongs to the kernel or the adapter.
5. **INVALID vs DENY** for unknown capability, cross-scope resource and stale revision: confirm host behavior treats all non-allow statuses as fail-closed.
6. **Prefix matching** is case-sensitive and string based; confirm canonicalization (adapter) is the sole defense against case and encoding aliases.
