# Session state, modes, and gates

The enforcement layer's contract: where session state lives, how modes and phases move, exactly what each gate checks, and the approval token's lifecycle. Source of truth: `writ/session/` (a package; `bin/lib/writ-session.py` is the CLI facade hooks call when the daemon is down) and `writ/server/routes/{gate,session_state}.py`.

## 1. The session cache

One JSON file per session: `$XDG_STATE_HOME/writ/session/writ-session-<sid>.json`, default `~/.local/state/writ/session/` (`WRIT_CACHE_DIR` overrides; the default is deliberately not `/tmp`, which systemd empties at boot; that wipe once destroyed every cache and presented as `mode=None`). It is outside the install, so a plugin upgrade keeps every session's mode and approvals. Set a mode with `writ mode set <mode> <session_id>` (the plugin's `bin/` is on the Bash tool's PATH).

**Schema** (single source `_default_cache()`, `writ/session/cache.py`; missing keys are backfilled on read, evolution is additive): mode, `current_phase`, `gates_approved`, `loaded_rule_ids` and `loaded_rule_ids_by_phase`, `always_on_rule_ids`, `remaining_budget`, `context_percent`, `files_written`, `analysis_results`, `pending_violations`, `invalidation_history`, `escalation`, `paused_work_state`, `is_subagent`, `is_orchestrator`, `parent_session_id`, `agent_type`, `citation_log`, `coverage_scope`, `source_type`, `verification_evidence`, `quality_judgment_state`, `queried_rules_by_file`, `phase_transitions`, `project_root`, and friends.

Two fields that look redundant and are not: `loaded_rule_ids` doubles as the ranked-query *exclude* list, so always-on rules are tracked separately in `always_on_rule_ids`; merging them would make always-on rules unretrievable and their citations read as hallucinated.

**Concurrency**: atomic writes (unique temp file, fsync, rename); read-modify-write under a per-session flock, reentrant per thread; a raising mutation writes nothing. Sub-agent caches are separate files keyed by `agent_id`; at commit time their per-file queried rules union into the parent's record.

**Session identity**: `$CLAUDE_SESSION_ID` > `$CLAUDE_JOB_DIR` basename > **None** (`resolve_current_session_id`, `writ/session/cache.py`). There is no third tier. The two that were there both answered "which session am I" with "whichever one moved last": the `/tmp/writ-current-session` pointer is one file per machine that every session's UserPromptSubmit hook overwrites, and the newest-cache-by-mtime glob read a directory every project shares. Callers now fail loud instead (the hook-facing CLI exits 2 naming the two env vars; `writ doctor` reports no session), because a wrong answer here writes a mode, an approval or an audit scope into somebody else's session and no log shows it happened. On a harness-rotated session id, the SessionStart hook carries the **mode only** into the fresh session, same project only; gates are never inherited.

**Compaction boundary**: PreCompact drops full rule objects (keeps ids); PostCompact is the authoritative recovery signal for *state*: budget resets to 8,000, the phase-scoped exclusion list clears, and the sticky-rule preference clears. Neither compaction event reaches the model, so re-orientation is deferred rather than delivered there: Claude Code's validator rejects a PostCompact `hookSpecificOutput` reply outright and bare PostCompact stdout lands only in the CC debug log (observed on a real `/compact`, 2026-08-14), so `cmd_reset_after_compaction` sets `post_compact_pending`, `writ-postcompact.sh` itself emits nothing, and `writ-rag-inject.sh` emits the mode-and-phase state line plus the re-verify directive on the next `UserPromptSubmit`, clearing the flag as it goes (pre-compaction verification output is second-hand).

## 2. Modes

`MODE_CONFIG` (`writ/session/mode_engine.py`) is the single source; five modes: `conversation`, `debug`, `investigate`, `review`, `work`.

- **`mode set`** always re-initializes: phase to the mode's initial phase, gates cleared, denial counts cleared, `project_root` stamped from cwd. "Gates cleared" means **this session's** `gates_approved` and this session's `.approved` artifacts (`_clear_gate_artifacts` takes the session id and refuses to default it); a sibling session's approvals in the same repo are untouched, which the flat project-wide path it replaced could not promise.
- **`mode init`** (the auto-router's entry) is a no-op when a mode is already set; it can never wipe a live gate cycle.
- **`mode switch`** out of work snapshots `{phase, gates, phase-scoped rules}` into `paused_work_state`; switching back restores it. The debug-to-work transition seeds `plan.md`'s `## Root Cause Evidence` from `debug.md` (idempotent, skipped when restoring a paused implementation phase).
- Auto-routing (`bin/lib/writ_mode_hint.py`, standalone stdlib for hot-path safety) fires only on unset mode: audit/explore/research shapes route to `investigate`, build shapes to `work`.

## 3. The write gate

`_can_write_check` (`writ/session/gates.py`) evaluates in strict order:

1. **Credential deny, every mode, overrides every exemption**: secret directories (`/.ssh/`, `/secrets/`, `/.gnupg/`, `/.kube/`), then credential basenames and extensions (`.env` minus templates, `*.key`, `*.pem`, `id_rsa`, `kubeconfig`, ...). Path-based; the file is never opened.
2. **Exemptions, each logged, never silent**: the Writ install's own tree; `~/.claude/settings.json` / `settings.local.json` (exact basenames, `realpath`-resolved to kill symlink escapes); then the ROLE SCOPE (below); then the PROJECT BOUNDARY for a dispatched sub-agent (below); then the GATE INHERITANCE arm (2d, below); then sub-agents (`is_subagent`) bypass what is left: the orchestrator already passed the human gate, and a worker whose role declares no scope is not re-policed outside that project.
2b. **Role scope**, the only arm here that can DENY. It fires only for a cache a real dispatch created (`cache_source == "subagent_start"`) whose role was OBSERVED (`agent_type` non-empty and not `unknown`, `role_source` not `unresolved`) and whose role DECLARED a scope (`role_write_scope` is a list, empty included). The scope is stamped once at dispatch from the role's graph node and read from the session cache, so a write costs no query: the gate runs in two processes (daemon route and CLI fallback) and a write-time lookup would deny in one and allow in the other. It reads FOUR cache fields and never `mode`, `current_phase`, `gates_approved`, `parent_session_id` or `project_root`, so no parent state widens or narrows a child: the parent's approval is why the dispatch exists, never an input to its scope. A refusal is `[ENF-ROLE-SCOPE]`, names the role and the declared patterns, and names NO escape, because there is none: no approval, phase change or mode opens a role boundary, only a human editing the role node. It is logged as a `write_attempt` with `gate_status=role_scope_deny` and deliberately NOT as a gate denial, because `denial_counts` feeds the escalation that names an approvable gate. Every other combination returns no opinion and today's decision stands: absence is not a policy. Two ordering consequences: the skill-dir exemption still runs FIRST, so the scope is inert on the Writ install itself, and the special-file rule below runs AFTER, so a scoped role is now judged for `plan.md` and `capabilities.md` too.
2c. **Project boundary (dispatched sub-agent)**, the second arm here that can DENY. It fires only for an `is_subagent` cache a real dispatch created (`cache_source == "subagent_start"`) whose role declares NO scope (`role_write_scope` is `None`), and it confines the child to the PARENT's project root, read through `parent_session_id` because a sub-agent cache deliberately stamps no `project_root` of its own. It DEFERS to a declared scope rather than stacking with it: a list, empty included, leaves `path_in_scope` the sole judge, because a declared scope is a narrower human-authored statement and running both would refuse a role whose scope legitimately names an out-of-project path with a message pointing at a plan that does not govern that role. It does NOT honor the plan's `## Files` (a sub-agent can write `plan.md` itself, so honoring the declaration here would be self-grantable); the `[ENF-PROJECT-BOUNDARY]` refusal names the only lever the child has, which is to stop and report to the orchestrator. No `parent_session_id`, or a parent with no project recorded, abstains: absence is not a policy. A `lazy_seed` cache abstains too, so cycle K's property holds (a lazily seeded cache decides exactly as no cache at all, reason string included).
3. **Special files**: `plan.md` writable pre-mode and through planning/testing (denied in implementation); `capabilities.md` always writable.
4. **No mode**: deny all writes (except the special files).
5. **Debug**: source edits denied until `debug.md` has a non-empty `## Root cause`.
6. **Review / conversation / investigate**: allow all.
7. **Work**: allow when both gates are approved; otherwise the exclusion list (`bin/lib/gate-categories.json`: tests, migrations, `__init__.py`, `.claude/` config and markdown) and the OS temporary directory are writable, and everything else denies with `[ENF-GATE-PLAN]` or `[ENF-GATE-TEST]`. The scratch allow sits AFTER the drift check, so `[ENF-GATE-DRIFT]` still refuses a scratch write, and it abstains when EITHER no `project_root` or no `scratch_zone` is recorded; it logs `gate_status=scratch_zone`. Every denial increments a per-gate counter; repeated denials escalate the hook decision from deny to ask.
7b. **Project boundary (work mode)**, guarding BOTH allow arms above and neither deny. An approved plan is authority for ITS project, so the both-approved allow refuses a resolved path outside the resolved project root unless the plan's `## Files` section declares that ABSOLUTE path; before this arm existed, an approved plan for one repo authorized a write to any absolute path on the filesystem (measured: `/etc/passwd-probe.txt`, ALLOW). The exclusion allow is bounded too, and that is not defensive: `*` spans `/`, so `*/tests/*` is satisfied by `/any/other/project/tests/x.py` and would otherwise be a one-line bypass reachable before any approval. It can only convert an ALLOW into a DENY, so every pre-approval refusal keeps its tag. ONE exempt zone: `tempfile.gettempdir()`, because the mechanism is "storage the OS designates as ephemeral" and not a directory with a particular name. It is resolved ONCE at `mode set` and stamped into the session cache as `scratch_zone`, NOT resolved at write time: the gate runs in two processes and `tempfile.gettempdir()` is a per-process answer, so a zone resolved per call let the daemon and the CLI fallback allow and deny the same path (measured). A session carrying no stamped zone therefore gets NO exemption and never a live fallback, and its refusal names `mode set` as the repair instead of claiming the temporary directory needs no declaration. The zone is SKIPPED when the project root is itself inside it (a project living in the temp directory would otherwise exempt every sibling beside it). The escape is not self-grantable: adding a `## Files` bullet changes plan.md's bytes, so `plan_md_hash` changes, `approved_gates_for_plan` drops both gates, and `[ENF-GATE-DRIFT]` blocks every write until the user replies `approved` again. Both sides are `realpath`-resolved and a relative envelope path joins the RESOLVED ROOT, never `os.getcwd()` (the daemon's cwd is Writ's own install dir, which carries `.git`, `pyproject.toml` AND a `plan.md`). The declaration is parsed section-scoped with the approval validator's own annotated-bullet regexes, so a path merely mentioned in `## Analysis` and a reason-less bullet both widen nothing. Refusals are `[ENF-PROJECT-BOUNDARY]`, name the action (declare the absolute path in `## Files`, ask the user for a fresh `approved`), and log one `write_attempt` with `gate_status=project_boundary_deny`, deliberately NOT a gate denial, because `denial_counts` feeds the escalation that names an approvable PENDING gate and the remedy here is an edited plan. An empty or relative recorded `project_root` abstains and keeps today's allow; a recorded root of `/` contains everything. In non-work modes the boundary does not apply at all: none of them has a plan, so none has a declared surface to derive it from or an escape to name. Recorded in `docs/adr/ADR-project-write-boundary.md`.

Glob caution for the exclusion list: `*` spans `/` and matches the raw path, so a directory-shaped glob exempts any depth and `..` escapes it. Keep patterns extension-anchored or exact filenames. A `write_scope` uses the same glob dialect but is matched against `os.path.realpath(file_path)`, because over-matching is safe for an EXCLUSION list and unsafe for an ALLOWLIST: judged raw, `*/tests/*` would be satisfied by `<dir>/tests/../../elsewhere.py` and by a symlink planted under `tests/`. A scope constrains the KIND of file, not the tree: a sub-agent cache carries no `project_root` on purpose, so `*_test.*` also matches `/etc/nginx/conf_test.conf`, which is still strictly tighter than the unconditional allow it replaces.

The same check serves the Write/Edit/NotebookEdit tools (`/pre-write-check`, which also returns file-context RAG on allow) and Bash-mediated writes (`writ-bash-write-gate.sh` extracts redirect and copy targets quote-aware, plus write targets inside interpreter one-liners such as `python -c` and `node -e`, and calls `/session/{sid}/can-write` with each). That former Bash-side gap is CLOSED: the classifier used to send only cwd-contained targets and drop the rest, so a Bash write outside the hook's cwd never reached the project boundary above, measured as a heredoc write succeeding to a path the Write tool had just refused. Out-of-repo targets now emit an `outside` row and take the same `can-write` round trip, and the pre-approval scratch cost that created is removed by the scratch-zone arm in item 7 above. One caveat when reading the Bash-side tests: fixtures that record no `project_root` see that arm abstain, so their refusals are door-agreement checks in a rootless session rather than real pre-approval scratch behavior, which `tests/test_write_door_parity.py` pins with a stamped root. The runtime-lens read gate (`_can_read_code_check`) blocks Read/Grep/Glob on source until `debug.md` has real Evidence and Narrowing sections; it fails open on any internal error by design.

## 4. Work phases and validators

`planning -> (phase-a) -> testing -> (test-skeletons) -> implementation`. Advancing from a terminal phase errors; it never silently no-ops.

- **phase-a** validates `plan.md`: `## Files` entries need a backticked path, a change type, and a reason; `## Analysis` non-empty; `## Rules Applied` must cite at least one rule id (or say "No matching rules"), and every cited id is checked against the union of loaded, phase-scoped, and always-on rule ids; anything outside that union is recorded as hallucinated. `## Capabilities` must be unchecked `- [ ]` boxes.
- **test-skeletons** requires a session-written test file with a real test signature, falling back to a project scan.

The validators are presence checks and say so; the correctness check is the human reading the artifact before approving. `apply_phase_advance` is the one mutation unit both the CLI and HTTP paths share (a cross-path parity test pins byte-identical cache effects): union the gate into `gates_approved`, move the phase, clear that gate's denials, roll the phase rule bucket to history, record the transition, clear a matching escalation.

**Re-opening planning: `replan approved`**. During implementation `plan.md` is refused with `[ENF-GATE-PLAN]`, and a plan change is what re-arms the gates, so a session that needs to amend its plan has nothing to advance and `approved` does nothing. The exit is one phrase, typed by the **user** and matched as the whole prompt (lowercased, surrounding whitespace and a trailing `.`/`!`/`,` stripped): `replan approved`. `bin/lib/approval_match.py::classify` returns the `replan` tier for it ahead of the embedded tier, and `auto-approve-gate.sh` mints a token bound to the `replan` gate and spends it in the same process on `writ-session.py reopen-planning` (a local CLI call, deliberately not an HTTP route: "the daemon is unreachable" is one of the states this escape exists for).

It fires only when all four hold, read from the one `current-phase` call the hook already makes: the state read parsed (a mode, and `next_gate` actually reported), mode `work`, phase `implementation`, and no gate pending. Anything else changes nothing and answers with what *is* pending. `cmd_reopen_planning` re-checks mode, phase and the pending gate from the cache, so the guard is not bash-only, and every refusal names one reason out of a closed set (`not_work_mode`, `not_implementation`, `gate_pending`, `state_unknown`, `token_invalid`, `token_not_replan`, `token_claimed`).

What it clears: the phase returns to `planning`, `gates_approved` and `gates_approved_plan` are emptied, `paused_work_state` and `denial_counts` are cleared, and this session's `*.approved` artifacts are deleted. It reuses `mode_engine._mode_set` for all of that rather than re-implementing gate clearing, adding only the `user-replan` transition trigger. **The result is stricter than the state it escapes**: `plan.md` becomes writable again, but with nothing approved every non-excluded write denies with `[ENF-GATE-PLAN]`, so source writes resume only after phase-a and test-skeletons are approved again against the revised plan. A replan-bound token authorizes nothing else (`_next_pending_gate` never returns `replan`, so both advance paths refuse it as a gate mismatch, and `/promote-candidate` requires an empty gate line). One `plan_reopened` row lands on the audit stream with `from_phase`, `to_phase`, `gates_cleared` and `confirmation_source: pattern`; a refusal writes `plan_reopen_refused`. A Bash command naming the reset subcommand is refused with `[ENF-GATE-STATE]`, so the agent cannot take this path itself.

**Plan-boundary enforcement after approval**: every write is analyzed post-hoc; at the boundary, a confirmed violation of a rule that was loaded at planning time invalidates phase-a (a sentinel file makes the *next* hook run exit blocking) and deletes the `.approved` artifact. Three invalidation cycles set an escalation with a differential diagnosis (`same-rule`, `different-rules`, or `mixed`), cleared only when the escalated gate advances.

## 5. The approval token

The anti-self-approval keystone, `writ/session/gate_token.py` plus `hooks/scripts/auto-approve-gate.sh`:

- **Minted** only by the hook, only when the *user's typed prompt* matches an approval pattern (`bin/lib/approval_match.py`: exact set, small-edit fuzzy, bounded regexes; fail-closed), only if no token already exists. `secrets.token_hex(16)`, chmod 600, at `/tmp/writ-gate-token-<sid>` (deliberately `/tmp`: byte-identical path with the bash writer; a reboot costs one re-approval, not a session).
- **Claimed atomically**: `os.rename` to a unique name means exactly one of N concurrent claimers wins; claiming *is* consuming, which closed a real double-advance race.
- **Spent by**: a successful advance, or a failed artifact validation (a changed artifact needs fresh approval). **Not spent by**: no pending gate, or an unresolvable project root.
- **Consumers**: `/advance-phase` and `/promote-candidate` only, the two routes that move workflow or write canon. Both validate the target gate *before* claiming. A tokenless attempt logs `agent_self_approval_blocked` to the audit stream and refuses.
- Two confirmation sources, one endpoint: the pattern path (`auto-approve-gate.sh`, `confirmation_source="pattern"`, only in work mode during planning/testing) and the tool path (`/writ-approve`, `confirmation_source="tool"`, which must send `cwd` because the server cannot substitute its own working directory). Approval writes a `<project_root>/.claude/gates/<session_id>/<gate>.approved` artifact: an audit record, not the source of truth. The `<session_id>` component is the isolation boundary (one python source, `writ/session/locators.py::gate_dir`, mirrored byte-for-byte in bash as `writ_gate_dir`): the flat per-project path it replaces let one session's approval read as approved to every other session in the same repo, and let `mode set` in one session delete another's. The accepted cost is that **approvals do not outlive the session that earned them**: `writ-session-end.sh` writes each artifact's metrics row and then removes it, so a new session re-approves.

## 6. Investigate mode's gates

Lens table (`writ/session/investigations.py`): `code` -> synthesis gate (advisory), `web` -> triangulation gate (**hard**), `runtime` -> the debug gates. Coverage uses a frozen denominator (`--freeze-scope`; re-freeze needs `--force`), examined = citations plus queried files; the synthesis gate requires a frozen scope and at least one examined in-scope file and explicitly claims nothing more. Triangulation requires citations from two independent registrable domains and fails closed at zero. Web content is auto-captured into citations by the WebFetch/WebSearch hook; Bash output auto-captures as runtime evidence in debug mode. Audit fan-out partitions the frozen scope first-fit-decreasing at 2,000 LOC / 30 files per worker, rolls coverage up, aggregates findings with contradiction surfacing, and ranks partitions by attention score.

## 7. Sub-agent lifecycle

2d. **Gate inheritance (dispatched sub-agent)**, the third arm here that can DENY, and the last one before the blanket allow. The bypass below justifies itself by the orchestrator having already cleared a human approval gate; this arm checks that claim instead of assuming it. It asks the PARENT's own `_can_write_check` what the parent may write right now, and refuses the child exactly where the parent is refused, with `[ENF-GATE-SUBAGENT]` quoting the parent's own reason because resolving that resolves this. It is not a second predicate for "which gate does this path need": the parent's checker is the judge, so the two cannot drift apart. ENF-SYS-002 position: the authoritative decision is the human typing the phrase and the hook recording it in `gates_approved`; this arm READS that record and never re-decides it, so it cannot contradict an approval, only refuse where none exists. Staleness cuts both ways and both are correct: a parent that clears the gate after dispatch reads as cleared, and a parent whose plan drifts reads as blocked, which is the state in which the parent itself may no longer write. ABSTAINS on: not a sub-agent, `cache_source != "subagent_start"`, no `parent_session_id`, an unreadable parent cache, and a parent NOT IN WORK MODE. That last is load-bearing, not defensive: only work mode has gates, and a parent with no mode is refused by its own checker with `[ENF-GATE-MODE]`, which would turn this arm from "inherit the gates" into "deny every dispatched write". MEASURED CAUSE, 2026-09-21: parent `f053345b` sat at `current_phase: testing` with `gates_approved: ['phase-a']`, was refused five times by test-skeletons, then dispatched sub-agents that wrote 24 files under 28 `subagent_bypass` rows, three of them files the parent had just been refused.

**What clears an approval.** Four things, and the fourth is new on 2026-09-21: `mode set` (fresh workflow state), a replan (`replan approved`), plan DRIFT (plan.md's digest no longer matches what was approved), and now COMMIT COMPLETION. When a commit resolves the last unresolved claim of the plan a session's gates are bound to, `commit_capture._expire_completed_approval` clears `gates_approved` and `gates_approved_plan` and returns the phase to planning. Before it, nothing retired an approval when its work finished: measured 2026-09-21, a session still carried both gates bound to a plan hash from a cycle three days and one unrelated task earlier, and source writes would have been allowed under it. The condition is EVERY declared path, not any, so a plan finished across several commits keeps its approval until the last file lands, and the resolved set is read across the project's Decisions rather than from one commit's file list. It can only ever REMOVE an approval. It abstains on: no session id, no resolvable plan.md, a plan declaring no files, a session not in work mode, and a session with nothing approved. The declared list comes from `plan_harvest._extract_files`, the canonical `## Files` parser, so a path mentioned only in `## Analysis` is not a declaration and cannot complete a plan.

`SubagentStart` creates the worker's isolated cache: inherits mode (read **file-direct** from the parent's cache, never daemon-first; a divergent daemon once served `mode=None` to every worker), phase, and approved gates; resets budget and rules; sets `is_subagent`. The CC payload carries only `agent_type` (no task text), so start-time RAG falls back to a role-derived query; rules reach workers via `additionalContext`. Dispatch discipline rewrites confident generic dispatches to the five `writ-*` roles in work/investigate/unset modes and asks on ambiguity (escapes: `[general-purpose]`, `[writ:dispatch-ok]`). `SubagentStop` records completion metrics, drains the worker's telemetry buffer, records a reviewer verdict, and runs the transcript tripwire: it is the only reliable read window on a sub-agent transcript, because Claude Code deletes those files when the session ends. One deliberate exception to agent-id keying: pending-test markers key on the RAW parent session id, because only the parent's Stop hook ever reads them.

## 8. Failure posture: fail open, by decision

When the daemon is unreachable (and, for gates, when a decision helper crashes outright, NARROWED by the 2026-09-08 refinement two paragraphs down: a decision block that could not run now asks), enforcement hooks allow rather than block: the pre-write dispatch and the Bash write gate proceed without a decision, Stop-time enforcement does not fire when mode resolution fails, and advisory checks skip. This is a deliberate availability-over-enforcement decision (user directive 2026-08-01): an infrastructure outage must never lock a user out of their own repository. Two boundaries hold regardless: credential-path denial in the Bash gate needs no server and stays closed, and the approval token cannot be minted or spent without the daemon, so workflow *advancement* (as opposed to raw writes) still halts. The compensating control is visibility, not blocking: gate crashes surface as hook-error notices rather than silence, degraded checks say so on stderr, and the audit stream records what ran. Audits should treat fail-open-on-outage as the specification, not a defect.

**The first of those two boundaries was FALSE above roughly 128 KiB until 2026-09-08, and the correction is worth stating rather than quietly editing.** "Credential-path denial in the Bash gate needs no server and stays closed" was true of the SERVER and false of the COMMAND LENGTH: the gate handed the command to its extractor as one environment string, Linux caps a single argv/env string at `MAX_ARG_STRLEN` (32 pages, 131,072 bytes), and `2>/dev/null || true` swallowed the `execve` failure, so the empty result read as "nothing to gate". Measured: a credential probe of 131,014 characters denied and one of 131,060 was silent, rc 0. The same shape sat on the Write/Edit door (silent at 131,000 bytes of content and above) and on the worktree gate. All three now hand the payload over on a channel with no per-string cap and OBSERVE whether their decision block finished, so no command length can disable an arm (`docs/adr/ADR-hook-exec-argument-boundary.md`, amendment 2026-09-08). **THERE WAS A FOURTH DOOR, and "all three" is why it is named here rather than left for the next reader to discover:** `writ-memory-policy-guard.sh` denied a rule-weakening auto-memory write at 200 bytes and at 131,000 and ALLOWED IT SILENTLY at 200,000, because it built its scan program out of a nested `python3 -c` on the content's own argv, so over the cap the outer program became a syntax error rather than a failed exec; its content now goes on a `printf` pipe to `bin/lib/memory-policy-scan.py` (all three sizes DENY, measured), its allow requires a POSITIVE verdict word rather than an empty string, and a missing or unrecognized verdict ASKS through the same `writ_decider_fault` posture as the other three (`docs/adr/ADR-hook-exec-argument-boundary.md`, second amendment 2026-09-08).

**The refinement to the posture, stated as two different states.** A DECIDER THAT COULD NOT RUN ASKS; it does not allow. The daemon being unreachable is still a fail-open, because the local fallback decides and the outage is an outage; a decision block that crashed or could not be reached is a different claim, and the honest answer to "this cannot be trusted" is the prompt, which the Bash gate already gives for an unresolvable write target. Each such fault writes two positive records: one `[WRIT CRITICAL]` line on stderr and one `gate_decider_incomplete` row on the audit stream (bounded to `hook` and `stage`, both source literals). A MACHINE WITH NO `python3` is the one case that still allows: it exits 0 and prints exactly one `[WRIT CRITICAL]` line naming that no Writ Bash or write decision can be made there at all, because every Writ decision path is interpreter-bound, so an ask would imply a protection that does not exist while making write-shaped commands unusable. What is NOT claimed: the credential arm is closed without a server and at any command length, but it is not closed without an interpreter, and no bash-side copy of the classifier will be added to pretend otherwise (a second source for the organization's hardest boundary would drift against `writ.session.gates._is_credential_path`).

## 9. Observability of enforcement

Every gate decision (allow and deny), mode change, phase advance, self-approval block, invalidation, promotion, verification-evidence record, and citation lands on the 365-day `audit` stream (`writ/shared/logging.py`); hook executions and timings land on `metrics`. `writ audit-session <sid>` renders a per-session timeline; `writ analyze-friction --rule-effectiveness` computes per-rule denial stick rates. The citation log in the cache is a bounded working set; the durable copy is the stream, written only after the cache write succeeds.
