webauthn-rs 0.6.2 verifies ceremony type, challenge, exact origin, RP id hash, user presence, user verification (forced Required for passkey authentication), backup-eligibility consistency, signature and allowed credential; counters checked only when nonzero (synchronized passkeys report 0 and are accepted; a decreasing counter is refused; `needs_update` returned for persistence). No credential-status hook: only active credentials are passed in (revocation is the ledger lookup). The challenge is generated by the library; with feature `danger-allow-state-serialisation` the authentication state is stored in our ledger record bound to the operation context (D-040 O-3). No web or session framework dependency.

Test authenticator (dev-dependency only): `webauthn-authenticator-rs` 0.6.2 `softpasskey` (UV flag with a falsify switch, synchronous; random keys; cannot simulate synchronized passkeys; adds 22 crates including tokio as a dev package only) or `passkey-authenticator` 0.6.0 (async without tokio; counters off by default, suits synchronized-passkey tests; adds BSD-3-Clause, Apache-2.0-only and Zlib crates).

Listener: `tiny_http` 0.12.0 is effectively unmaintained (last release 2022); hyper and axum need tokio (forbidden in the broker); a minimal `std::net` listener adds no dependency (HTTP parsing is not a cryptographic primitive): loopback bind, Content-Length only, size caps, exact Host and Origin check (DNS-rebinding defence), CSRF token, CSP. Browser rules: `http://localhost` is a secure context; RP id `localhost` with origin `http://localhost:PORT`; an IP address is not a valid RP id.

## Recommendation (pending DR-1..DR-4)

New workspace crate (working name `writ-approval`) linked by the broker process, holding `webauthn-rs = "=0.6.2"` (`default-features = false`, `danger-allow-state-serialisation`; attestation not needed for the local profile) and the `std::net` loopback listener; `writ-kernel` and the broker's storage-independent logic stay free of it behind a broker-owned typed verifier trait. Dev-only: `webauthn-authenticator-rs = "=0.6.2"` (`softpasskey`) plus a synchronized-passkey fixture (`passkey-authenticator` or a p256-based fixture). Earliest adoption 2026-11-14 (14-day rule); about ten release-age pins needed for transitive crates.
