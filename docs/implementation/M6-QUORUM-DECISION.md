## Approved recommendation

- Identify high-stakes criteria only in the verified signed acceptance policy. Enroll a closed set of eligible scoped evaluator identities for each such criterion. Use existing required-class, artifact, workflow, version and revision bindings. A pack, evaluator report or caller cannot designate or exempt a criterion.
- Require two eligible mechanical or authenticated evidence evaluators of the criterion's required class, from a signed eligible set of at least two. Count distinct evaluator IDs, key IDs and verification material, and require distinct explicitly reviewed independence groups. Review common ownership, implementation, evidence provenance, execution environment and key custody when assigning groups. Different IDs do not establish independence. Human signoff retains its existing purpose and any independent requirement. Model-assisted results remain advisory.
- Count current, unambiguous passes. An eligible authenticated failure blocks promotion even if two pass. Abstentions, missing records, ambiguity and unavailable trust never count as passes. With fewer than two eligible independent passes, keep the criterion incomplete. Bind the exact reviewed evidence set and signed policy to prevent dropping a failure from the submitted set. Reject conflicting duplicates from one evaluator and require the trusted source to attest completeness for that evaluation attempt.
- Reverify current evaluator and key status and exact bindings at promotion. Order publication, revocation and protected promotion under the existing authoritative fence. Atomically record promotion and consume the record and every counted evidence identity. Refusal consumes nothing. Restart and replay recover the authoritative receipt by exact identity.
- Version the signed acceptance-policy contract to include criterion quorum configuration and a trusted eligibility and independence-group binding. Version the authenticated record envelope to carry a bounded complete set of criterion evaluations with stable evidence IDs and separate verifiable provenance for each. Preserve existing authenticated records and their signing bytes for criteria that still use existing semantics. An older record cannot satisfy a newly quorum-required criterion. Refuse unknown versions and unsupported combinations.

The D-061 acceptance obligations cover two eligible passes, each eligible class, one pass, missing and abstaining evaluators, an authenticated disagreement, attempted omission of a failure, repeated evaluator or key identity, aliased key material, shared independence group, advisory and wrong-class evidence, exact scope and version changes, current revocation in both commit orders, unavailable trust, cross-attempt replay, partial consumption, audit and storage failure, and exact restart recovery. Verify legacy acceptance for unchanged criteria and legacy refusal for quorum-required criteria using the same trusted policy path.
