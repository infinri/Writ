3. Root cause
   The test builds the P-FS job script with fs_script(&cfg, &sentinel), where the sentinel is
   <CARGO_MANIFEST_DIR>/../target/writ-probe-<pid>-unit-fs/sentinel/secret, and then, to run it
   outside bubblewrap, rewrote the job's own write ": > /work/.writ-probe" with a blanket
   .replace("/work/", "<scratch>/"). On the runner CARGO_MANIFEST_DIR is
   /home/runner/work/Writ/Writ/hostsys, so the sentinel path itself contains "/work/" and was
   rewritten to /home/runner<scratch>/Writ/Writ/target/.../sentinel/secret, a path that does not
   exist. cat failed, and the script correctly reported read_sentinel=refused. Locally the
   checkout is under /home/<user>/workspaces/..., which contains "/workspaces/" but not
   "/work/", so the defect was invisible.

   Hypotheses ruled out by the reproduction below: user or uid differences, 0700 scratch
   directories, cleared environment and PATH, umask, inherited descriptors, deadline, coreutils
   implementation (the runner image ships coreutils 9.5-1ubuntu2+0.0.0~ubuntu25, the uutils
   transition package; the failure reproduces with GNU coreutils 9.4, so the cat implementation
   is not the cause).

5. Correction (test only; hostsys/src/probes.rs, inside #[cfg(test)] mod tests)
   The test now replaces only the exact line ": > /work/.writ-probe\n" (asserting it occurs
   exactly once) with a write to the shell-quoted scratch path, asserts that the shell-quoted
   sentinel path appears verbatim in the script it runs, and prints the job stdout when the
   read_sentinel assertion fails. No production function, readiness rule, probe script,
   evaluation or negative control changed; git diff of non-test code is empty.

   Why it is valid: the assertion's purpose is that the P-FS script, run without containment,
   reaches a readable sentinel (so a "refused" in the real job means containment, not a broken
   script). The old test silently ran a different script from the one under test whenever the
   host path contained "/work/"; the new test runs fs_script's output unchanged apart from the
   single job-local write, and fails loudly if that line or the sentinel path is not present.

   Verification of the correction:
   - In the "/work/" clone: writ-hostsys lib tests 32 passed, three runs, plus one run under
     env -i with umask 077 (32 passed).
   - Mutation: in the clone, fs_script's sentinel read pointed at a missing file
     ("secret-missing"); the corrected test fails (the sentinel-path assertion), so the check
     still discriminates.
   - Worktree: see TEST-EVIDENCE entry for fmt, clippy -D warnings, workspace tests, check_deps.

6. Production probes and security implications
   Production probe_fs uses fs_script output verbatim inside bubblewrap; there is no path
   rewriting outside the test, so the runner path cannot alter a production job. A production
   sentinel path that were somehow unreadable would make the job report read_sentinel=refused
   (a potential false ok), but probe_fs only reports ok after its negative control: the same
   script with an extra read-only bind of the sentinel directory must report
   read_sentinel=reachable, otherwise the control fails and readiness blocks (readiness test
   control_that_did_not_fail_turns_ok_into_error_and_blocks). A false missing is fail-closed.
   No other test or production code performs a substring rewrite of job scripts (grep of
   hostsys/src for .replace( finds only this test and a sysctl key mapping in facts.rs).
