# M5a-12 guest gate draft

The workflow calls the unprivileged `run-containment <approved-sha>`. On the separate CI base, install that entry point and `guest-gate` as root-owned executables in `/opt/writ-ci/bin`, and install `gate_evidence.py` there read-only to the runner. Give the dedicated runner sudo access to that single fixed `guest-gate` executable with environment reset and no SETENV. The executable checks its sole argument against the host's binding. Configure the runner user without other privilege grants, groups or credentials. The owner must first review and verify the full base and matrix implementation.

For each authorized run/attempt, have the external provisioner perform these steps before registering the runner.

1. Prepare a fresh guest named `writ-ci-<run_id>-<attempt>` and obtain owner designation for that name using the two-line disposable marker, mode 0600. Keep the general AppArmor user namespace restriction enabled and the guest clock, filesystem and lifecycle under the host's control.
2. On the trusted host generate uncompressed `git archive --format=tar <exact-reviewed-sha>` from the admitted upstream repository. Record its SHA-256 in the single-use approval. An unsupported tree entry, including any symlink, requires a new review of archive admission. Install those same immutable bytes at `/opt/writ-ci/source.tar`. The gate hashes and extracts the same open file into a new private attempt directory. Executed checks consume only that extracted tree and independently verified build artifacts.
3. Provide root-controlled `/opt/writ-ci/reviewed-sha` for the workflow, `required-results.json` and `binding.json` in the same directory, and an empty root-owned `/var/lib/writ-ci` directory mode 0700. Bind all seven fields exactly as implemented in `gate_evidence.check_binding`. The manifest hash covers the raw manifest file bytes, including its final newline. The source archive digest, base image digest and required manifest digest must each match the host approval. Pin the baked control files and matrix executable in the admitted CI base.
4. Install a separately reviewed root-owned `/opt/writ-ci/bin/containment-matrix` for this profile. Its interface is `prepare`, then `verify <required-result-id>` for each manifest entry in order, then `teardown`. It runs with the verified source root as its working directory. Each verification returns 0 only after observing the complete applicable J-9 or M5a-07 condition and validating the private raw observations for this attempt. The control result for each probe covers **every** subcontrol specified by the binding revisions to J-9 and J-11. Record expected and observed conditions and individual exits privately. Require the launcher path where specified, a live disposable desktop and authentic failure causes. Unavailable, skipped, stale, duplicate, unobserved or partial checks must return nonzero. Preparation and teardown failures also fail the gate. Supply each toolchain and artifact digest through a separate trusted staging process or build from the verified tree on compatible Ubuntu. This draft has no accepted matrix executable. Direct job-UID trials and the aggregate trial exit cannot implement the full contract.
5. After the externally imposed deadline or terminal job event, stop the guest. Use a bounded isolated reader for the one evidence file at `/var/lib/writ-ci/attempt/evidence.json`. The wrapper writes that file only after teardown succeeds and the evidence passes local validation. The external controller repeats validation against **its own** binding and approved manifest, checks the authenticated terminal job status, verifies destruction, and publishes through its restricted App. Each driver invocation has separate private stdout, stderr and exit status in the attempt directory. Never export those files, the runner workspace or arbitrary paths as public artifacts.

The host may retain a private failure record from its own control path. A missing evidence file is a failure. The separate reference-guest checklist, real host lifecycle and negative infrastructure tests still require live verification. Keep the draft workflow inactive.
