# Private host controller integration

The controller is an offline-tested host library. Install the reviewed controller, evidence validator and approved manifest on the private host. Use a single publisher and a persistent operator-only state directory with mode 0700 and umask 077. Run the control loop under `exclusive_controller(state_directory)`. Invoke `recover(db, host)` at startup and `run(db, host, approval, manifest_bytes, policy)` for each new approval. The global nonblocking lock serializes the host. SQLite persists the identity, challenge, cutoff, evidence digest and cleanup outcome before publication. A repeated attempt and an older attempt on the same SHA are refused. Keep the state directory across restarts and back it up privately.

Supply a private owner approval source for the exact run, attempt, job ID, Writ SHA, control SHA, source archive digest, image digest and manifest digest. Set `ControlPolicy` from trusted configuration. Its repository and ref identify the private control repository and protected workflow ref. Its numeric group ID identifies the restricted group. An approval record must authorize exactly one attempt. The webhook or dispatch payload cannot create approval records.

The host adapter implements these calls. Adapter errors raise exceptions. The record argument contains the approval, policy, binding, queue deadline and overall deadline. Use the record's run, attempt and host challenge to derive a unique, rediscoverable resource namespace before creating resources.

| Call | Required effect |
| --- | --- |
| authenticate_queued(record) | Read the authenticated Actions API records, run head repository, fork flag, actual protected workflow revision, restricted group configuration, owner dispatch authority and host approval. Verify the fixed source repo and reviewed SHA against the fetched branch. Return the normalized fields in verify_job. In particular, restricted_group requires selected private repository and exact selected workflow access, public access disabled. |
| provision(record) | Create a fresh VM and JIT single-job registration from the verified image. Enforce network isolation and stage the exact credential-free reviewed source and manifest. Bind every resource to the record. Partial creation must be discoverable by destroy. |
| wait_running(record) | Confirm the exact job started on the registered guest. Refuse cancellation, timeout or any other runner. |
| wait_terminal(record) | Return freshly authenticated terminal facts for the same job, including conclusion and assigned_to_this_guest derived from the registered runner ID. |
| stop_and_read_evidence(record) | Stop the guest and extract at most 65,536 bytes from a one-way channel or isolated reader. Reject oversize records before allocating their contents. Return bytes. |
| cancel(record) | Idempotently cancel the exact private run after checking identity. A terminal run is already settled. |
| destroy(record) | Revoke unused registration material, deregister the runner and destroy the VM and all attempt-specific storage, including seeds. Handle missing and partially created resources. |
| absent(record) | Return boolean true only after independent authoritative readback confirms the runner, registration and all VM resources are gone. |
| publish(record, state) | Publish only the dedicated context to the approved original Writ SHA using the host-only App. Enforce per-SHA fencing and reject stale attempts server-side even on delayed retries. Before sending success, verify the host deadline is still open. Bound acknowledgement by that deadline and reconcile an ambiguous delivery as failure. Return only after checking the exact App result, or raise. |

Use bounded requests for every external call. Provisioning and queue operations must finish by the host queue cutoff, and terminal polling and extraction by the overall cutoff. Use bounded cleanup and status operations with independent retries and a host supervisor that forcibly stops a hung controller or adapter; ensure the adapter cannot leave an asynchronous create operation running after timeout or destruction. Run a separate watchdog to reconcile dirty lifecycle records and revoke/destroy overdue resources even across process death and host restart. Recover conservatively publishes failure for interrupted attempts. An unsuccessful publish remains a retry obligation. Before admitting a newer attempt, ensure its pending status has been acknowledged and the merge gate cannot reuse an earlier success during publisher outage.
