[J-1](../../docs/implementation/M5-INTERFACES.md#j-1-process-and-privilege-model-revision-4-binding-d-046-c-1-h-2) defines the identity and denial requirements. [J-9](../../docs/implementation/M5-INTERFACES.md#j-9-reference-environment-and-capability-probes-review-m-4-h-3-l-3-lead-decision-m-5) requires a live reference-host observation and all eight negative controls. [J-11.10](../../docs/implementation/M5-INTERFACES.md) specifies the disposable desktop session for the reference VM. Run operational checks only in the owner-designated Ubuntu 24.04 guest with rollback.

The [test contract](../../hostsys/src/desktop/mod.rs) and [evaluator](../../hostsys/src/desktop/evaluate.rs) remain test-only. The [collector](../../hostsys/src/desktop_collect/mod.rs) shares identity parsers and reconciliation across its fixture tests and guest inventory entry point. ## Guest inventory

Build the reviewed SHA with `cargo build --locked -p writ-hostsys --bin writ-desktop-inventory`. Stage the binary in the prepared reference VM. After [owner designation and rollback verification](PROVISIONING.md#owner-designation-and-guest-trials), the owner supplies the current guest boot ID and configured role UIDs and runs the binary as root inside that guest.

```text
writ-desktop-inventory VM BOOT_ID SERVICE_UID JOB_UID AGENT_UIDS DESKTOP_UIDS
```

Use comma-separated lists for the agent and desktop UIDs. The expected marker must be a root-owned mode-0600 regular file at `/etc/writ-disposable-vm`, with the provisioned content and the chosen guest name. The collector verifies that name against the guest hostname. It requires KVM or QEMU, Ubuntu 24.04, PID 1's filesystem root and mount/UTS/PID/user/network namespaces, the initial PID and user namespaces, and an unfiltered guest procfs. It refuses a separate procfs subtree or masked proc view. Collect from a quiescent guest with inspectable processes and threads in the admitted PID, user and network namespaces.

The guest operator must establish and verify files-only NSS before attempting an inventory. Ubuntu setups with a `systemd`, SSSD or any other additional account source need a reversible guest-only configuration change. Require exactly `passwd: files` and `group: files` in `/etc/nsswitch.conf`, and `initgroups: files` if that rule is explicit. Preserve the original configuration through the guest rollback. The collector validates the rule set and reads the trusted local passwd and group files itself. The Linux inet and Unix SOCK_DIAG handlers must be available in the guest; arrange for built-in or preloaded handlers if module autoload is disallowed.

| Obligation | Observation | Open verification |
|---|---|---|
| `Scope`, identities and groups | Checks the boot and namespace scope around both samples. Enumerates process leaders and every visible thread. Pinned proc directories, directory entry identities, start times, all four UIDs and GIDs, supplementary groups and repeated scans bind credentials to observed processes. Any thread matching a configured agent UID makes its process relevant. It derives the selected PIDs from those facts. | Obtain actual guest evidence, executable or launch provenance, independent login, terminal and session identity. |
| `TcpListeners`, `UnixSockets`, `AbstractSockets` | Enumerates each visible task's FD links, including non-agent tasks, and groups socket inodes by stable process holder. Independently reconciles IPv4 and IPv6 listening and addressed Unix sockets from proc and kernel SOCK_DIAG. Records IPv6 binding mode and interface, socket cookies, Unix type and state, and exact Unix address bytes from SOCK_DIAG. A proc Unix display string corroborates a rendering only. | Verify positive guest coverage and the caller-visible filesystem path and mount identity. Test every applicable transport or protocol obligation in separate runs. |
| Other rows below | The account home field and the inventory provide candidates for later classification. | Establish filesystem metadata, display authorization, credential stores, logind, seat and device state, process and terminal targets, and the remaining observations. |

J-1 and J-9 scope this inventory to configured desktop UIDs. For each TCP listener, the proc UID must agree with the INET_DIAG UID. For each addressed filesystem or abstract Unix socket, the collector requests UDIAG_SHOW_UID and requires the kernel socket UID from UNIX_DIAG_UID. This identifies the socket in the admitted user namespace. A pathname's file owner, a service name and a process holding a descriptor each answer a different question. Passing an FD can leave a process holding a socket owned by another UID.

For every candidate, establish at least one observable holder and validate each holding thread's real, effective, saved and filesystem UIDs against its process leader. Exclude the socket only when the kernel UID and **every** holder UID are outside the configured desktop set. If either side includes a desktop UID, report the endpoint only when every holder agrees with its kernel UID. Any disagreement then makes the entire inventory unavailable. For example, a root-owned socket shared by root and a non-desktop service is outside scope. The same holders on a desktop-owned socket cause refusal, including after the desktop closes its last FD. Both sweeps still compare the full descriptor and diagnostic views, including excluded candidates. J-1's separate requirements for display, session, authentication and other actual service targets still apply.

The line-oriented `writ-desktop-inventory/1` output contains scope, account, selected process, endpoint and holder rows. Unix address bytes are hexadecimal, including the leading NUL of abstract addresses, any embedded bytes and the terminating NUL of a filesystem address. Relative names remain as bound. Identical filesystem names can refer to separate inodes or a path that has since changed. The command reports a missing endpoint class per desktop UID and ends a completed inventory with `end`. Treat exit status 3 as unavailable and accept an inventory only on exit status 0 with the terminating record. Review socket addresses before sharing the output.

The sweep bounds file sizes, rows, processes, threads, descriptors, netlink messages and time. It uses a 15-second collection deadline and a 16-second command watchdog. Linux scheduling or an uninterruptible kernel operation can delay process termination. Any unreadable descriptor or task, unsupported view, ambiguous holder, truncated input, or sampled disagreement leaves the inventory unavailable. An unreaped zombie with inaccessible namespace links or a named pending Unix accept without an inode can cause refusal. Retry only after establishing a quiet guest window.

These are serial observations. An identity held open through the sweeps and a stable socket cookie help detect replacement. Brief changes between reads, changes restored between observations, and changes after the final check can escape detection. Coverage is limited to endpoints visible in the admitted network namespace. Socket references retained outside process descriptor tables, imported descriptors from a foreign network namespace and other socket families do not establish target coverage in this command. An in-scope endpoint without an observable, consistent holder causes refusal. There is no socket or path access attempt and no denial, isolation, negative-control or readiness finding.

## Scope, completeness and evidence

- Derive the expected service, job, agent and desktop UIDs from configuration. Collect the identity view separately. Match the complete account sets and require one record per configured agent and desktop combination. Run agent-side attempts as the specified agent with the actual groups, login session and terminal verified. Root-side observations establish the target inventory.
- Capture every required target as an opaque identifier for a single collection window. For each obligation validate both inventory snapshots, require the same nonempty target set in both, and match one typed outcome per target. Empty inventories, collection errors, stale or changed identities, targets appearing or disappearing during collection, duplicate targets and incomplete observations block the probe. Reconcile before and after collection and report the result as point-in-time. Distinguish confirmed denials from incompatible clients, timeouts, disappeared targets, unreadable inventories and command failures.
- Require a live disposable session and real test targets for every required class. Set up the target applications, display protocols and credential surfaces called out below in the guest. A missing target remains missing. The operator records version, identity and control provenance without retaining cookies, credential material or raw environments. The fixture boundary takes the collector's typed statements as inputs. It cannot detect a real endpoint omitted from both submitted inventories. Future production integration needs independently reviewed collectors that establish those statements and exclude fixture data.
- Capture each negative control independently from its own deliberately perturbed run. Match the specific detection to the planted target, the tested identities and the control run. A failed setup, generic execution failure or unrelated detection leaves the control incomplete. Restore the baseline after each control and confirm the positive run separately.

## Mandatory observations

In the matrix, **VM** means evidence from the designated guest. **Session** also requires a live test desktop session and its actual targets in that guest. The test column names the typed obligation. Each row needs an accepted fixture, omission and unavailable cases, and rejection of an unsafe or unproven outcome.
