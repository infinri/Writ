# P-AGENT-DESKTOP collection and test obligations

[J-1](../../docs/implementation/M5-INTERFACES.md#j-1-process-and-privilege-model-revision-4-binding-d-046-c-1-h-2) defines the identity and denial requirements. [J-9](../../docs/implementation/M5-INTERFACES.md#j-9-reference-environment-and-capability-probes-review-m-4-h-3-l-3-lead-decision-m-5) requires a live reference-host observation and all eight negative controls. [J-11.10](../../docs/implementation/M5-INTERFACES.md) specifies the disposable desktop session for the reference VM. Run operational checks only in the owner-designated Ubuntu 24.04 guest with rollback.

The [test contract](../../hostsys/src/desktop/mod.rs) and [evaluator](../../hostsys/src/desktop/evaluate.rs) use typed observations. The [fixtures](../../hostsys/src/desktop/fixtures.rs) exercise every required observation and control. The [read-only collector](../../hostsys/src/desktop_collect/mod.rs) runs against injected fixture inputs. Both modules compile only for tests. The existing `writ-readiness/1` contract and required-probe validation still apply.

## Fixture-backed collector coverage

| Obligation | Collected or reconciled | Remaining source and observation work |
|---|---|---|
| `Scope`, identity and group membership | Parses local passwd and group records separately from configured UID and PID expectations. Reconciles primary and listed group membership, named Writ groups, distinct role accounts, and real, effective, saved and filesystem IDs and supplementary groups for each selected agent process. Brackets each credential read with the process PID and start ticks. | Prove complete guest account visibility and process selection. Verify agent executable or launch provenance, independent login, true thread coverage, terminal and session identities. NSS beyond local files is outside this collector. |
| `TcpListeners`, `UnixSockets`, `AbstractSockets` | Parses IPv4 and IPv6 listener and addressed Unix proc tables. Joins endpoints to socket inode and process holder records, including holder PID and start ticks. Cross-checks owner credentials with observed selected agent processes when they overlap. Reconciles separate before and after inventories for each desktop UID. An absent class is unavailable for that UID. | Produce complete, namespace-bound FD and credential observations in the guest and corroborate owner and address data with an independent socket source. Resolve lossy Unix display names and filesystem path identity before any checks. Run each transport or protocol check separately. |
| All other typed rows below | The passwd home field and generic socket names yield candidates for subsequent classification. | Establish target existence and classification, filesystem metadata, display authorization, logind, seat and device state, process and terminal inventories, credential stores and every remaining observation. |

The source supplies complete, independently acquired reads within one guest view. It reports unreadable, unsupported or incomplete inputs, including a truncated stream that ends after a complete line. Each snapshot is bracketed by the boot ID and PID, user and network namespace IDs. Owner rows are synthetic `inode pid start_ticks uid` records for distinct process holders. Each UID must represent all four observed process UID fields. A future guest source must establish coverage and ownership from actual evidence, including visibility across the processes in scope, and decline mixed or unresolved credentials. Unix proc display names are accepted only as faithful fixture representations of addresses. Distinct inodes sharing a displayed filesystem pathname remain separate observations. An access check needs independent evidence of which socket that pathname reaches. Unnamed Unix entries have no addressable inventory target.

Reconciliation compares observed account and process facts and the target sets, including process starts and socket holders. This detects differences visible in the samples. A change that reverses between samples, or PID reuse within a single start-time tick, can escape detection. A guest source needs stronger process identity and sampling guarantees. The collector makes no access attempts and emits no denial, isolation, negative-control or readiness finding.

## Scope, completeness and evidence

- Derive the expected service, job, agent and desktop UIDs from configuration. Collect the identity view separately. Match the complete account sets and require one record per configured agent and desktop combination. Run agent-side attempts as the specified agent with the actual groups, login session and terminal verified. Root-side observations establish the target inventory.
- Capture every required target as an opaque identifier for a single collection window. For each obligation validate both inventory snapshots, require the same nonempty target set in both, and match one typed outcome per target. Empty inventories, collection errors, stale or changed identities, targets appearing or disappearing during collection, duplicate targets and incomplete observations block the probe. Reconcile before and after collection and report the result as point-in-time. Distinguish confirmed denials from incompatible clients, timeouts, disappeared targets, unreadable inventories and command failures.
- Require a live disposable session and real test targets for every required class. Set up the target applications, display protocols and credential surfaces called out below in the guest. A missing target remains missing. The operator records version, identity and control provenance without retaining cookies, credential material or raw environments. The fixture boundary takes the collector's typed statements as inputs. It cannot detect a real endpoint omitted from both submitted inventories. Future production integration needs independently reviewed collectors that establish those statements and exclude fixture data.
- Capture each negative control independently from its own deliberately perturbed run. Match the specific detection to the planted target, the tested identities and the control run. A failed setup, generic execution failure or unrelated detection leaves the control incomplete. Restore the baseline after each control and confirm the positive run separately.

## Mandatory observations

In the matrix, **VM** means evidence from the designated guest. **Session** also requires a live test desktop session and its actual targets in that guest. The test column names the typed obligation. Each row needs an accepted fixture, omission and unavailable cases, and rejection of an unsafe or unproven outcome.

| Requirement | Typed test obligation | Collector obligation and environment |
|---|---|---|
| Dedicated, distinct, non-root identities and group membership | `Scope` plus exact agent × desktop coverage | **VM.** Reconcile configured and observed UIDs. Inspect named groups, effective membership including primary GIDs, rejecting ambiguous names and GID aliases, own primary groups, and actual agent process credentials. Require `writ` and `writ-job` with only their own primary groups, no explicit listed members and no other accounts in those groups, `writ-agents` with exactly the configured agents, and each agent with only its own group and `writ-agents`. Confirm desktop accounts have only their own primary groups, those groups exclude agent and job accounts, and desktop accounts are outside the three Writ groups. Record distinct login identities. |
| Human home and browser profiles | `HomeRead`, `HomeList`, `HomeWrite`, `BrowserRead`, `BrowserList`, `BrowserWrite` | **Session.** Inventory configured homes and active profile paths, including Firefox, Chromium, Chrome and snap profiles when present. Use disposable files and directories to verify read, listing and write denials as the agent. |
| Approval state kept in the browser profile | `BrowserStateContained` | **Session.** Inspect configured browser state and approval server storage paths. Verify fixture session cookies, session storage and cached approval content remain confined to the profile. Verify the server creates no token or cookie files elsewhere. Use test state and report findings without token values. |
| Xauthority and X11 authorization policy | `XAuthorityRead`, `XhostPolicy` | **Session.** Inventory actual authority files and display allowlists. Verify file read denial and absence of local-user, wildcard or family grants allowing the agent. |

Check every target. A confirmed connection denial or a protocol-specific authentication refusal is typed evidence. A successful connect without proof of protocol refusal stays unverified.
